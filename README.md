# 叙境 StoryRealm · v1.0

**让一个想法，成为可以走进去的故事。**

叙境是连接本地模型的互动小说与角色创作平台。通过 AI 引导构思世界、人物和开场，在可编辑的草稿基础上开始故事，并由你决定后续行动。

- AI 辅助新建作品、角色卡与玩家身份设定。
- 世界书、摘要记忆、场景状态和四个可选行动建议。
- 人物资料补全、美化与撤销，小说式正文与篇幅控制。
- 原生 HTML / CSS / JavaScript，无前端构建步骤。
- 作品和聊天保存在当前浏览器；连接本地模型时可离线使用。

当前版本 **1.0.0**，界面标注为 **v1.0**。更新记录见 [CHANGELOG.md](CHANGELOG.md)。

## 快速开始

### 准备环境

- 现代浏览器，支持 ES modules、import map 与 `<dialog>`。
- Python 3，用于提供本地网页服务；无需安装 Python 第三方包。
- 已可运行的 llama.cpp `llama-server` 与兼容的 GGUF 模型。
- Windows 一键启动还使用系统的 `curl`；Node.js 仅用于运行开发自测。

仓库不包含模型权重或 llama.cpp 程序。

### Windows 一键启动

1. 将 `start.local.example.bat` 复制为 `start.local.bat`。
2. 填写 `LLAMA_DIR`（llama.cpp 文件夹）和 `MODEL`（GGUF 模型完整路径）。
3. 双击 `start.bat`。脚本会启动模型与网页服务，并复用已运行的服务。

```bat
@echo off
set "LLAMA_DIR=C:\path\to\llama.cpp"
set "MODEL=C:\path\to\models\your-model.gguf"
```

`start.local.bat` 属于本机配置，已被 Git 忽略。本机原有路径已保留在该文件中。
不使用本机配置时，默认查找项目内的 `runtime\llama-cpp\llama-server.exe` 和 `models\model.gguf`。

批处理脚本使用 ASCII 文本与 CRLF 换行。修改脚本时请保留这种格式，以免 Windows 解析命令时出错。

### 手动启动

在 llama.cpp 文件夹启动模型服务，模型路径换成自己的文件：

```bat
llama-server.exe -m "C:/path/to/models/your-model.gguf" -c 8192 -ngl 99 --jinja --host 127.0.0.1 --port 8080
```

示例按本地 GPU 推理配置，GPU 层数和上下文长度需适合自己的设备与模型。模型加载完成后，在项目根目录运行：

```text
python -m http.server 5173 --bind 127.0.0.1
```

浏览器打开 `http://127.0.0.1:5173`，默认模型地址为 `http://127.0.0.1:8080`，可在顶栏修改。请通过网页服务访问，避免直接双击 HTML。

### 数据与备份

资料保存在当前浏览器的 localStorage；更换浏览器、访问地址或端口会使用另一份存储。清除网站数据会删除本地作品与聊天。作品配置和角色卡可通过界面导出备份；这两个导出入口不等同于完整聊天备份。

当前面向本机使用，尚未提供账号、云端同步或多人协作。

## AI 辅助新建作品

点击作品列表旁的 **「+ 新建」**，打开创作向导：

1. **故事方向**：想写什么题材、体验怎样的故事。
2. **背景与架构**：时代、地点、世界规则与主要矛盾。
3. **人物设定**：主要互动人物的性别、性格、经历、外貌体型，以及配角。
4. **我是谁**：玩家身份、性格、背景及与人物的关系。
5. **开场与节奏**：从哪个场景开始，希望怎样推进。

第一问提供方向，后续问题由 AI 根据已有回答提出，每步都有参考选项，也可自由输入或点击「这一步交给 AI」。如果已有完整构思，可以只写一句或一段话，直接生成草稿，无需答完五步。

生成后先进入 **可编辑预览**，可修改作品名、世界背景、角色卡、玩家身份、配角、世界书及开场白。点击「确认创建作品」后才正式保存并切换过去：主要互动人物生成新角色卡，玩家生成新的「我的身份」，配角作为本作品常驻世界书条目保存。当前最多一位主要互动人物、四位配角和八条额外世界书。

- 关闭窗口自动暂存，重新点击「+ 新建」可继续；生成失败时保留回答和已有草稿。
- 预览与访谈不会改动旧作品、人物或聊天；创建失败会尝试回滚本次存储修改。
- 默认启用摘要记忆和每次回复的四个行动建议，可在预览中取消；聊天仍可自由输入。
- 创建后仍可到「角色卡」「我的身份」「世界书」等面板细化。修改角色卡后点击「应用到作品设定」；开场白会同步保存与显示。
- 保留「直接创建空白作品」，不使用 AI 也能创建。
- AI 使用页面配置的模型服务；提问失败会切回内置引导问题，生成草稿需要模型可连接。

`node test-story-creator.mjs` 提供 22 项模拟回归。独立浏览器验证了完整流程、错误重试、暂存恢复、旧数据隔离、预览转义、延迟请求丢弃及创建后聊天。另在本地 llama.cpp 完成一次实际追问与完整草稿生成，测试使用虚构的图书馆故事，不访问用户作品或聊天。

## 核心机制

### 提示词组装

设定块按 `order` 升序拼接成系统提示词：

```
[世界观] order 0
[玩法]   order 1
[角色设定] order 2
[主提示词] order 3
        ↓ 拼接
    system message
```

### 世界书三级触发控制

| 字段 | 选项 | 作用 |
|---|---|---|
| 触发区域 | 用户 / AI / 两者 | 决定扫哪一侧的文本 |
| 匹配格式 | 或（任一）/ 与（全部） | 多关键词的判定方式 |
| 影响范围 | 提示词 / 前置词 / 后置词 | 决定注入到哪个位置 |

**影响范围的权重差异**（越靠后权重越高）：

```
system（设定块 + 提示词域世界书）
  ↓
前置词（紧贴历史之前）
  ↓
对话历史
  ↓
后置词（权重最高）
  ↓
用户本轮输入
```

**递归触发**：条目内容里提到别的条目关键词时会自动带出来。
例：「贝茜是一头牛，和鲁弗斯是好朋友」→ 自动带出「鲁弗斯是一只狗」。默认递归 2 层。

**关键词支持正则**：写成 `/小(明|红)/` 即可。

### Reply Example 自定义面板

让模型在回复里输出 HTML 面板：

```
<Reply Example>
<div class="panel">当前状态：好感度 42</div>
</Reply Example>
```

前端会把它渲染成内嵌面板。渲染走 `iframe[sandbox=allow-same-origin]`，模型产的 HTML 无法触碰主页面。

### 变量面板状态格式

在「其他」中启用变量面板后，默认提示词会要求模型在回复末尾追加：

```text
<State>{"好感度":42,"地点":"图书馆"}</State>
```

状态标签不会显示在聊天正文中，会合并保存到当前作品；点击状态栏的「清除」可以重置。也兼容独立的 `json` 代码块。

### 摘要记忆与行动选项

在「其他」中启用摘要记忆后，对话达到阈值会自动整理较早消息，只保留最近几条并把摘要带入后续提示词，也可以手动点击「立即生成摘要」。

启用「让 AI 提供 4 个行动选项」后，模型会用 `<Choices>["选项1","选项2","选项3","选项4"]</Choices>` 返回选项。点击选项只会填入输入框，用户仍可修改、忽略或直接自己输入。

### 结构化剧情回复

在「其他」中启用「结构化剧情格式」后，回复可以包含 `<Scene>` 场景信息、`<State>` 状态、`<Memory>` 短期/长期记忆和 `<Choices>` 行动选项。场景和剧情记忆会保存在当前作品，并在后续提示词中提供给模型；标签本身不会显示在正文里。场景格式与行动选项可独立开关。可选的「显示简短演绎检查」只显示模型提供的简短检查内容，不要求输出完整思维链。

示例：

```text
正文……
<Scene>{"time":"第1天 14:30","world":"现代都市","location":"高速公路"}</Scene>
<State>{"好感度":5}</State>
<Memory>{"shortTerm":["角色主动试探"],"longTerm":["两人开始旅行"]}</Memory>
<Choices>["继续开车","询问目的地","停车休息","自己输入"]</Choices>
```

## 角色卡系统（含 AI 辅助创作）

角色卡页还支持“AI 整理并回填角色卡”：把一整段世界背景、人物关系和开场剧情粘贴进去，AI 会按角色名、外貌、性格、背景、说话方式、故事情境、开场白和示例对话分类回填。回填后仍可手动修改，确认后再点击“应用到作品设定”。

对标 SillyTavern 角色卡字段，额外做了 AI 辅助。

### 用法：两步式 AI 创作

1. 在「角色卡」Tab 写一句话构思（如"会武功的图书管理员，表面冷漠其实很护短"）
2. 点 **AI 生成方向** → 约 9 秒，得到 4 个差异明显的方向卡片
3. 点中你喜欢的那个 → 点 **展开选中方向** → 约 37 秒，生成完整设定
4. 不满意的地方，改完后点该栏的 **AI 美化**

### AI 美化四种模式

点任意字段旁的「AI 美化」后选择：

| 模式 | 作用 |
|---|---|
| 润色 | 保持原意，只提升表达质量 |
| 扩写 | 补足细节，扩到 2-3 倍 |
| 精简 | 删冗余，留最有力的表达 |
| 具体化 | 把「善良勇敢」换成具体行为 |

实测：`她很善良，对人都很好。` → 具体化后 →
`她总是主动询问他人的近况，并用温和的语气耐心倾听，在朋友遇到困难时，她会毫不犹豫地提供具体的帮助或情感支持。`

### 免 AI 快速路径：6 套模板

傲娇 / 温柔治愈 / 高冷疏离 / 玩世不恭 / 自卑敏感 / 强势御姐
套用后可继续用 AI 扩写，不消耗等待时间。

### 角色卡字段

对齐 SillyTavern V2 规范：name / description / personality / scenario / first_mes / mes_example / creator_notes / tags

自有的 `tagline`（一句话身份）和 `speechStyle`（说话方式）通过 `【标记】` 承载，
导出成标准 V2 JSON，导入时自动拆回——**可与外部卡互通**。

### 应用到作品

点「应用到当前作品」，自动生成 5 个设定块：

```
order 0  世界观    ← scenario
order 1  角色设定  ← 外貌 + 性格 + 背景
order 2  说话风格  ← speechStyle
order 3  示例对话  ← mesExample（教语气和格式）
order 4  主提示词  ← 角色扮演引擎指令
```

开场白会同步到作品的 greeting 字段。

## 玩家身份（Persona）——「我」是谁

对标 SillyTavern 的 User Persona。这是角色卡的另一半：
角色卡定义**对方**是谁，Persona 定义**你**是谁。

### 为什么必须有

没有 Persona 时，模型不知道在跟谁互动，只能泛泛地演。
实测对比（同一角色、同一句输入）：

| | 设置了 Persona | 未设置 |
|---|---|---|
| 输入 | 「先生让我把这个交给你」 | 同左 |
| 反应 | 「既然你没带大脑出门…」**精准嘲讽新手** | 「眼睛长在脑门上只是装饰」泛泛毒舌 |

Persona 让模型知道对方是「新来的、紧张、什么都不懂」，反应才有针对性。

### 字段

| 字段 | 作用 | 是否进提示词 |
|---|---|---|
| 名字 | 替换 `{{user}}` | ✅ |
| 性别与叙述代词 | 男、女、未设定、自定义；代词可自动或手动设置 | ✅ |
| 年龄、身高 | 人物的基础资料，可留空 | ✅ |
| 体型体态、穿着、声音、个人特征 | 描述这个人物的外形、风格与辨识特点 | ✅ |
| 能力、目标、相处偏好与边界 | 约束互动方式和行动动机 | ✅ |
| 外貌、经历与背景 | 玩家形象与过往经历 | ✅ |
| 身份 | 我是谁、和对方什么关系 | ✅ |
| 性格 | 影响对方如何对我 | ✅ |
| 头像 | 角色栏和消息气泡显示 | ❌ |
| 备注 | 仅自己看 | ❌ |

### 详细人物资料

角色卡和「我的身份」共用性别与详细人物字段。选择男/女后展开相应人物详情，切换性别保留已填内容，并将代词恢复为按性别自动选择。新建人物默认为「未设定」，不会根据名字猜测性别。
角色卡编辑后需点击「应用到作品设定」；玩家资料编辑后自动保存并用于当前作品。角色卡 AI 展开/故事分类支持填写这些字段，未知资料留空。
角色卡导出时，完整字段保存在 `data.extensions.sil_profile`，并在标准描述中追加可读副本。旧卡片和旧身份无需重新创建。

### AI 填写人物资料

角色卡和「我的身份」均提供「让 AI 帮你填写人物」入口。写一句构思即可，例如「沉稳的山城摄影师，喜欢独自旅行」；已填资料时可不写构思。

- **AI 补全空白**：只填写空白项，保留已有描述。
- **AI 优化设定**：润色描述并补充细节，保留已填姓名、性别、年龄和身高；代词仍由界面自动选择或用户指定。
- **细节栏的 AI 美化**：体型、穿着、声音、个人特征、能力、目标、相处边界各有独立按钮。有文字时润色，空白时参考已有设定补全；只回填该项，旁边可单独撤销。男女与自定义人物、角色卡与玩家身份均支持。
- **撤销本次填写**：撤销最近一次 AI 回填，保留你随后手动修改的字段。撤销记录只在当前页面会话保留，刷新后已保存的资料不受影响。
- 支持外貌、性格、背景及体型、穿着、声音、个人特征、专长、目标、相处边界等详情；玩家另支持身份，角色另支持一句话身份、说话方式与故事情境。
- 人物资料自动保存；角色卡检查后仍需点击「应用到作品设定」。生成过程中修改的字段不会被旧结果覆盖，切换人物后会放弃尚未应用的结果。
- 仅发送当前人物的公开设定，不发送私人备注、头像或聊天历史。新增细节属于创作建议，填写后仍可编辑。

### 小说式正文

后续对话、开场白生成、示例对话和文字润色统一要求小说式自然段。动作、神态与环境直接描写，台词使用中文双引号“”，界面保留引号并高亮。无需手写 HTML。
既有作品中的内置括号格式指令会兼容更新；历史聊天、已有开场白与自写人物资料不会被批量改写。场景、状态、记忆和行动选项的解析标签继续使用。

运行 `node test-profile-ai.mjs` 可检查 AI 补全、优化、撤销、切换人物、错误恢复及小说格式。使用模拟模型回复；浏览器交互也已在独立测试会话验证，不影响用户数据。

页面已通过 `index.html` 中的 import map 统一脚本版本，避免旧缓存造成 `safeJson` 导出缺失、整页按钮无响应。更新后在原页面强制刷新一次即可。维护代码时同步递增映射中全部模块、入口脚本和样式的版本；`node test-module-loading.mjs` 检查映射是否完整。

```
  ├─ 世界观
  ├─ 【玩家身份】    ← 插在这里
  ├─ 角色设定
  ├─ 说话风格 / 示例对话
  └─ 主提示词
```

**为什么放在角色设定之前**：让模型先明确「我在跟谁、在什么关系里互动」，
再读角色行为规则。反过来容易被角色指令带偏，忽略玩家身份。

### 6 套身份预设

我自己 / 初来乍到 / 圈内人 / 外来者 / 学生 / 无名者
套用后可继续编辑。预设身份会带来明显不同的互动风格。

## 关键实现细节

### 聊天记录按「作品:角色」双键存储

```js
function chatKey(configId, cardId) {
  return cardId ? `${configId}:${cardId}` : configId;
}
```
向后兼容：旧数据（无 cardId）仍能读出。

### 宏替换时机

在 assemble 的最后统一做 `{{char}}` / `{{user}}` 替换，
所以任何地方写这两个占位符都能生效，包括世界书内容和变量面板提示词。

### Persona 与角色名的空值处理

- `charName` 为空 → 不替换 `{{char}}`，保留占位符
- `userName` 为空 → 保留 `{{user}}`

避免出现「你好，是要帮  做事吗」这类残缺句子。

## 篇幅控制（2026-10-11 新增）

### 问题现象
回复字数偏少（约 200-300 字），期望 2000 字以上。

### 根因诊断（实测对比，重要结论）

**主因是提示词，不是采样参数。** 三组对比（同一句输入）：

| 配置 | 输出字数 | 结束原因 |
|---|---|---|
| 原配置（t=0.85, max_tokens=800） | 255 字 | 模型主动结束 |
| 只加大 max_tokens=3000 | 281 字 | 模型主动结束 |
| 完整新采样参数 | 218 字 | 模型主动结束 |

**结论：光放开 token 上限没用**，模型会在 200-300 字处主动收尾。
另外原提示词里「动作简练」这句在**反向激励**短回复。

### 提示词档位实测效果

| 档位 | max_tokens | 实测字数 |
|---|---|---|
| 中| 900 | 733 字 |
| 长 | 1800 | 1742 字 |
| **超长** | **3600** | **2710 字** ✅ |

### 两处改动

**1. js/prompts.js（新增）** — 4 档预设提示词 + 建议 token 数。
epic 档写了明确的结构配比（环境 400 / 动作 600 / 心理 400 / 台词 400 / 推进 200 字）、
描写标准（动作拆到最小单位、五感具体、允许留白）、以及禁止条款（禁止概述跳过场景、禁止提前收尾）。

**2. js/llm.js** — 采样参数调优：

| 参数 | 原值 | 新值 | 原因 |
|---|---|---|---|
| max_tokens | 800 | 3000 | 硬上限太低 |
| temperature | 0.85 | 0.9 | 略提多样性 |
| top_p | 0.92 | 0.95 | 放开一点 |
| min_p | — | 0.05 | 比 top_p 更稳 |
| **repeat_penalty** | **默认 1.1** | **1.05** | **1.1 会让模型为避重复而提前收尾** |
| frequency_penalty | — | 0.2 | 话题延展 |
| presence_penalty | — | 0.15 | 同上 |

### 用法

「篇幅」Tab → 选档位 → 可自由编辑提示词 → 点「应用到作品设定」。

应用时保存到独立的「篇幅要求」设定块，并记录作品的 `length.preset` 与 `length.blockId`。
自定义内容保存在该设定块中，刷新、切换作品、导出再导入均可恢复；重新应用角色卡会保留篇幅要求。
面板会区分「待应用」和「已应用」，选择档位或修改文本后需点击应用。

`vars.maxTokens` 保存正文预算。发送时另为结构化场景/状态/记忆预留 800 tokens；未开结构化格式但启用变量面板时预留 400；四个行动选项另预留 200。例如超长档与结构化格式、选项同时启用时，请求上限为 `3600 + 800 + 200 = 4600`。
未应用篇幅、预算值无效或独立篇幅块被禁用/删除时使用 `llm.js` 默认值 3000。
token 数与中文字数没有固定换算关系，预留空间也不能保证所有模型都完整输出；实际字数仍受模型、上下文和服务端限制影响。

旧版只保存 `vars.maxTokens` 的作品会按预算恢复档位，并显示原主提示词。
再次应用时，可确认的原始篇幅预设会迁移成独立块；手动修改过的主提示词保持原样，其中如有旧字数要求，可在「基础设置」中同步调整。

### 回归检查（2026-10-11）

修复了 `send()` 将整个参数对象嵌套传入 `max_tokens` 的问题，以及篇幅面板未随作品恢复、覆盖主提示词和角色卡覆盖篇幅的问题。
运行 `node test-length.mjs` 可检查四档实际请求参数、默认值、草稿与应用、作品切换、导入导出、角色卡兼容和旧配置迁移。使用模拟 HTTP，不需要启动模型服务。

### 速度提示

此前本地样例中，2000+ 字约需 75 秒；这是特定模型与设备的记录。若生成较慢，可选择更短档位，实际字数与耗时仍由模型决定。
